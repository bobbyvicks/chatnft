# Patches

One file per change to `index.html`, kept as a record after it has been
applied. They are **archived, not runnable twice**: every one opens by
refusing to apply itself again, and the app is a single file so a second run
against a changed tree would fail its anchors anyway.

They are here because commit bodies cite them by name, and a name that points
at a session scratchpad points at nothing. That is the same rot the top of
`WORKLOG.md` describes, and it was found in this repo's own history on
2026-09-06: a commit explaining what eighteen mutants bought referred to
`scratchpad/mutate234-236.cjs`, a path nobody else had. The mutation
predictions moved to `tools/` for that reason, and these followed.

## What is in one that is not in the file it changed

The prose is not the reason to keep them — a patch writes its reasoning into
`index.html` as comments, and those travel with the code. Two things do not:

- **The `kit.save` checks.** What had to be true of the tree *before* the
  change, and what had to be true *after*. `patch236` refuses to run if a
  status folder could become a layer; `patch238` refuses if the self-clash
  guard is gone. These are the conditions the author was actually relying on.
- **The `RUN` blocks.** Arithmetic and equivalence proved before the change
  was believed, on data rather than on reasoning. `patch238` checks 87,480
  single-group cases and 6,561 overlapping ones against the implementation it
  replaced, which is the whole argument that the index is the same predicate;
  the old implementation is gone, so no test can make that comparison again.

## Reading one

The header says what was reported, what was measured, and what was
deliberately not done. Then the edits, each with its own anchor and its own
refusal. Then `kit.save`, which runs every check and a parse before a byte is
written — the repo's CHECK-FIRST-WRITE-LAST rule, which exists because
`index.html` is CRLF and a multi-line replace built with `\n` silently matches
nothing and reports success.

## One caveat

`patch237-rule-import.cjs` reads a rules file from an absolute path outside
this repo (`E:/X content/pixel art_/trait-records/...`), because the numbers it
proves are about that file. It will not run on another machine, and the file
itself is regenerated by its author — it gained three conditions and ten
traits between two readings on the evening of 2026-09-06. That is why its
checks assert the properties of the translation and print the counts, rather
than asserting the counts.
